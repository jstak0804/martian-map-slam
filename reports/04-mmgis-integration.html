Rebuilding the Survival Map on Top of NASA's Own Production GIS Platform

NASA-AMMOS/MMGIS는 MSL Curiosity, Mars 2020 Perseverance, Lunar VIPER가 실제로 쓰는 오픈소스 GIS입니다. 지금까지 우리가 직접 구현한 SPICE 조도 계산, 지평선 마스킹, 통신 가시선, 경로 비용함수가 전부 이 안에 이미 production 품질로 들어있습니다.

01

Sightline — 사실상 CLPS 챌린지 그 자체

Sightline 툴의 공식 설명을 그대로 옮기면: "지형 위에서 궤도선 또는 천체 목표물에 대한 가시선(line-of-sight)을 계산하고 시각화한다." 설정 예시를 보면 더 분명해집니다.

Sightline 설정 예시 (MMGIS 공식 문서 발췌)JSON
"sources": [
  { "name": "MRO", "value": "MRO" },
  { "name": "ODY", "value": "-53" },
  { "name": "TGO", "value": "TGO" },
  { "name": "The Sun", "value": "SUN" }   // 우리가 CLPS에서 계산하던 바로 그 태양
],
"observers": [
  { "name": "MSL", "value": "MSL" }       // 관측자(착륙지점/로버)도 그대로 설정 가능
]

게다가 기본 관측 기준좌표계(obsRefFrame)의 기본값이 IAU_MOON입니다 — 애초에 달 임무를 1순위로 염두에 두고 설계된 도구라는 뜻입니다. “Include Sun + Earth” 옵션 하나만 켜면, CLPS 챌린지가 요구하던 “태양과 지구 동시 가시성 비교”가 그대로 나옵니다.

CLPS 요구사항Sightline이 이미 제공하는 것
태양·지구 방위각/고도Results 패널의 Azimuth/Elevation/Range, Sky Dome 극좌표 플롯
지형 마스킹(스카이라인)Horizon Profile — 360° 지형 실루엣, 관측자 중심 ray-casting
조도/암흑 구간Composite 모드 — 시간대별 누적 가시성 히트맵
DTE 통신 가능/단절 구간Visibility Timeline — 가시(색상)/차단(회색) 바 차트, 최장구간 그대로 식별 가능
보증(assurance) 리포트사용 커널·DEM·해상도가 설정값으로 모두 기록됨
전략적 함의

CLPS 보고서의 핵심 요구사항 5개 중 사실상 4개가 설정만으로 해결됩니다. 팀이 다시 CLPS로 돌아가더라도, 새로 짤 코드는 거의 없고 달 DEM(LOLA)과 SPICE 커널을 Mission Config에 등록하는 작업이 핵심이 됩니다.

02

Isochrone — “최단거리를 넘어서”를 이미 풀어놓은 도구

Martian Map 브리프가 콕 집은 문제(“기존 모델은 경로 탐색을 단순 유클리드/다익스트라 거리로 축소시킨다”)를 Isochrone 툴은 정확히 반대로 풀어둡니다.

Isochrone 설정 예시JSON
{
  "data": {
    "DEM":   [ { "name": "지형고도", "tileurl": "...", "resolution": 256 } ],
    "slope": [ { "name": "경사",     "tileurl": "..." } ],
    "cost":  [ { "name": "우리CV위험도", "tileurl": "..." } ]  // 여기에 우리 risk grid를 꽂는다
  },
  "models": ["Traverse Time", "Isodistance"]
}
  • 타일 기반 Dijkstra가 브라우저 안에서 이미 동작 — 모든 픽셀이 8방향+나이트무브 16개 이웃과 연결된 그래프
  • data/slope/obstacle/cost 카테고리로 여러 레이어를 조합 가능 — 우리의 terrain_risk + temp_risk + wind_risk + radiation_risk 가중합을 그대로 “cost” 타일 하나로 공급하면 끝
  • “least-cost path”를 호버만 해도 보여줌 — 05절 경로탐색 요구사항을 그대로 충족
우리가 할 일

Dijkstra 엔진을 새로 짤 필요가 없습니다. /src/essence/Tools/Isochrone/models에 커스텀 모델 하나만 추가해, 우리 risk_score 공식을 cost 데이터 소스로 연결하면 됩니다. science_value(제제로 크레이터 등)는 음수 비용으로 넣으면 “가치 있는 곳으로 끌어당기는” 경로 탐색이 가능합니다.

04

그래서 우리가 진짜로 만들어야 하는 것

MMGIS가 대신 해주지 않는 부분만 남습니다 — 정확히 우리 팀의 차별화 지점과 일치합니다.

  • CV 지형 분류·바위 탐지 모델 — AI4Mars로 학습한 soil/bedrock/sand/big_rock 분류기 (MMGIS는 이런 모델을 갖고 있지 않음, 우리가 만든 산출물을 Data Layer로 "공급"하는 역할)
  • Isochrone 커스텀 비용 모델 — 우리 CV 위험도 + 환경 레이어를 하나의 cost 함수로 합치는 JS 플러그인
  • 더스트/방사선 전처리 파이프라인 — MCD·RAD 원시 데이터를 MMGIS가 읽을 수 있는 GeoTIFF/타일로 변환하는 스크립트
  • Devon Island/LROC 기반 SLAM 전처리 — 우리 스테레오 VO 결과를 MMGIS Vector/Data 레이어 포맷(GeoJSON)으로 내보내는 변환기
팀 피치에 쓸 수 있는 한 줄

“우리는 NASA가 실제 임무(MSL·M2020·VIPER)에 쓰는 오픈소스 GIS 위에, 그 플랫폼에 없는 유일한 조각 — Computer Vision 기반 지형 위험 탐지 — 을 얹었습니다.”

05

hazard_overlay.json → MMGIS Data Layer 변환

심화학습에서 만든 출력 포맷을 MMGIS가 바로 읽는 구조로 바꾸면 이렇게 됩니다.

mmgis-data-layer.jsonData Layer 설정
{
  "name": "CV Hazard Risk",
  "type": "data",
  "url": "Layers/HazardRisk/{z}/{x}/{y}.png",
  // auxiliary/1bto4b/rasterstotiles1bto4b.py 로 risk grid(.npy/.tif) -> 타일 변환
  "shader": {
    "type": "colorize",
    "units": "risk",
    "noDataValues": [-9999],
    "sigfigs": 2,
    "ramps": [["#1c6b73", "#a3781f", "#9c4a3a"]]
    // 우리 프로젝트 팔레트(teal -> gold -> rust) 그대로
  },
  "timeEnabled": true,
  "timeFormat": "YYYY-MM-DDTHH:mm:ssZ"
  // 더스트/기온처럼 날짜별로 바뀌는 레이어는 이 두 줄만 추가
}

변환 스크립트 하나만 있으면(risk grid → GeoTIFF → rasterstotiles1bto4b.py), 심화학습의 전체 CV 파이프라인 출력을 MMGIS에 바로 꽂을 수 있습니다.
