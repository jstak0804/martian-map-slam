## I1. 시나리오 심박 bpm 표시 정리

### 문제 [확인]
- 시나리오 심박은 `wToHr(k × 모델 대사량)`으로 만든다. 현재 모델 대사량(평지 444 W ≈ 1,515 BTU/h)이 Hoffmann 회귀식의 자료 범위(최상위 구간 > 1,200 BTU/h ≈ 153 bpm)를 넘는다.
- 그래서 평지 k = 1에서 206 bpm, 25% 급증 뒤 약 269 bpm이 화면에 나온다. 표시되는 곳은 세 군데다.
  - 시뮬레이션 세부(`심박 (측정 · 모델 기대)`, 템플릿 1238줄 부근)
  - 심박 그래프(1267줄)
  - 직접 입력 내보내기(1642줄)
- 산소 계산과는 무관하다. k = 심박 대사량 ÷ 모델 대사량이므로, 같은 식으로 환산했다가 되돌리면 상쇄된다.

### 방식: (가) 표시만 고친다 (계산은 그대로)
- 회귀 범위 상한 `HR_VALID_MAX_W = 1200 BTU/h × 0.29307 = 351.7 W`를 둔다. 같은 값을 `heart_rate_o2.py` 경고에서도 쓴다.
- 모델 기대 대사량이 이 값을 넘는 프레임이 있으면 다음처럼 바꾼다.
  - 세부 표시를 `심박 (합성값, 회귀 범위 밖)`으로 바꾸고, 툴팁/작은 글씨로 이유를 한 줄 적는다.
  - 그래프 제목을 `심박 (bpm, 합성값 — 회귀식 범위 밖)`으로 바꾼다.
  - 그래프 위 범위 밖 구간(351.7 W 초과에 해당하는 bpm 이상)에 옅은 띠를 그린다.
- 직접 입력 모드(사용자가 실제 bpm을 넣는 경우)에서는 표시를 그대로 둔다. 그 값은 측정값이기 때문이다.
- README와 데모 "계산 방법과 한계" 문구를 맞춘다.

```js
const HR_VALID_MAX_W = 1200 * BTU_W;   // Hoffmann 2021 회귀 자료 최상위 구간 경계
const hrOut = (mrW) => mrW > HR_VALID_MAX_W;
// paintSim: const synth = state.simScenario !== "custom"; const out = synth && hrOut(frame mrModel × kTrue)
```

### 고르지 않은 대안
- (나) 보행용 심박–대사량 관계로 바꾸는 것: 조사가 필요해서 대회 전에는 하지 않는다.

### 검증
- 하네스로 심박 예시를 돌려 세부 텍스트에 "회귀 범위 밖"이 나오는지 본다.
- 직접 입력 사례(#sim-custom과 같은 125/165 bpm)에서는 표시가 그대로인지 본다.
- 산소·k·로그 수치는 I2 회귀 테스트로 변하지 않았음을 확인한다.

## I3. 경보 규칙의 예비분 침범 스윕

### 문제 [관찰 1건]
- 예시에서 경보를 켜면 예비분 45 g 중 1 g을 쓰고 도착했다(44 g).
- 원인을 이렇게 추정한다 [추론]:
  - 경보는 "1분 뒤 위치에서 지금 k로 돌아갈 수 있는가"만 본다.
  - k 추정은 최근 10분 평균이라, 급증 직후에는 늦게 따라간다.

### 실험
- 템플릿에 `state.simLookMin`(기본 1)을 추가한다. 경보의 "1분 더 가면"을 "N분 더 가면"으로 일반화한다.
  - 기본 1이라 동작은 바뀌지 않는다. I2 테스트로 확인한다.
  - UI에는 노출하지 않는다. 분석용이다.
- 스윕 (하네스, `recalc/i3_alarm_sweep.json` 작업 생성 → `outputs_i/i3_alarm_sweep.json`):

| 축 | 값 |
|---|---|
| 목적지 | 거점에서 3~6.5 km 웨이포인트 중 15곳(계획 H1 후보 목록에서 균등 추출) |
| 시나리오 | surge, high, fatigue, model |
| k 근거 | 심박, 압력 |
| 누설 g/h | 0, 10 (압력은 "알려진 누설 빼기" 끔) |
| 미리 보기 N분 | 1, 2, 3, 5 |
| 산소 | 450 g |

  - 15 × 4 × 2 × 2 × 4 = 960회다. 1회 약 0.3초로 보면 수 분이다 [추정].
- 지표:
  - 경보로 돌아선 경우 중 예비분을 침범한 비율, 최대·중앙 침범량(g)
  - 산소 소진 비율
  - 경보 없이도 다녀올 수 있었는데 경보가 돌려세운 비율(과잉 경보)
- **결정은 결과를 본 뒤 사용자에게 받는다.** 기본 N을 바꿀지, k에 여유를 둘지 정한다. 이 계획에서는 기본값을 바꾸지 않는다.

## I4. 냉각수 추가 열 → 구조 예시·면적 (분석만)
- 근거: 계획 E 3번(CHANGELOG 13.1). 핸드북 그림과 비교해 역산한 추가 열은 22~44 W(가용 8.35 lb 가정) 또는 58~77 W(9.1 lb 가정)다.
  - 결정 E-a는 "0 유지"였다. 직접 소모율 비교로는 우리 식이 오히려 보수적이었기 때문이다.
- 데모의 "환경 열" q가 같은 역할을 하므로 하네스로 q = 0 / 25 / 50 / 75 W를 돌린다.
  - 기준 150 g 면적(냉각수 가득)과 냉각수 0.6 kg 면적
  - 구조 예시(sol 746): 판정, 구조대원 최소 냉각수, 탱크 대비 여유
  - 심박 예시: 도착 냉각수
- 출력: `outputs_i/i4_extra_heat.json`, CHANGELOG 표.
- 구조 예시가 깨지는 q가 25 W 이하이면 README 구조 예시에 "추가 열이 없을 때"라는 조건을 명시한다(문서만). 모델 기본값은 바꾸지 않는다.

## I6. Apollo 14 한 점 점검 (분석만)

### 비교 대상 [확인: Waligora & Horrigan 1975, `recalc/references/Waligora1975_metabolic_cost_EVA.pdf`]
- "Apollo 14 보행 2.9 km, 평균 2.4 km/h(0.67 m/s), 대사량 300 kcal/h(349 W)"
- 그림 1(속도-대사량)은 원문도 상관이 매우 약하다고 했다. 쓰지 않는다.

### 계산
- IST 평지 식(`ist_model_coefs.json`, TGAW 선형)에 달 무게를 넣는다. TGAW = (체중 + 우주복·PLSS) × 1.62 m/s²
  - 질량은 범위로 둔다(원문 확인 전 가정): 체중 70~80 kg, A7L 우주복 + PLSS 80~95 kg
  - 출처를 찾으면(NASA 문서) 범위를 좁힌다. 못 찾으면 범위 그대로 [미확인]으로 표시한다.
  - TGAW가 IST 범위(236~627 N) 안인지 확인한다.
- v = 0.67 m/s에서 대사량 범위를 구하고 349 W와 비교한다.
  - 경사 보정은 하지 않는다. Apollo 14 경로에 오르막(Cone 크레이터)이 있으므로 실측이 평지 모델보다 높게 나오는 방향이다.
  - Pandolf × 달 중력비(이전 방식)도 같이 계산해 어느 쪽이 가까운지 본다.
- 출력: `outputs_i/i6_apollo14.json`, CHANGELOG에 "한 점 점검이며 검증 아님"과 한계(우주복 차이, 보행 외 활동 혼입, 평균값)를 적는다.
