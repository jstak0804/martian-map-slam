### 반드시 고칠 곳: 시뮬레이션을 거리 단위에서 시간 단위로
zip은 매분 `STEP_PER_MIN = 0.92 × 60` m씩 나아간다. 로컬은 경사마다 속도가 달라서 그대로 두면 시간과 산소가 맞지 않는다.

```js
// pathTrack: 누적 거리 cd와 누적 산소 co에 더해 누적 시간 ct를 둔다 (edgeO2가 남긴 EDGE_T 사용)
function pathTrack(cells) {
  const n = cells.length, cd = new Float64Array(n), co = new Float64Array(n), ct = new Float64Array(n);
  for (let j = 1; j < n; j++) {
    const a = cells[j - 1], b = cells[j];
    const d = Math.hypot((b % W) - (a % W), ((b / W) | 0) - ((a / W) | 0)) * CELL;
    co[j] = co[j - 1] + edgeO2(a, b, d); ct[j] = ct[j - 1] + EDGE_T; cd[j] = cd[j - 1] + d;
  }
  return { cells, cd, co, ct, len: cd[n - 1], dur: ct[n - 1] };
}
// trackAt(tr, t): ct 기준 이분 탐색. 칸, 산소, 거리를 시간 t에서 선형 보간해 돌려준다.
// 진행: s(거리) 대신 tt(초)를 쓰고 1분 = 60 s씩 나아간다. 경로 끝에서 남은 시간은 서 있는 대사량(rest_mr_w)으로 채운다(zip과 같음).
// 경보의 "1분 더 가면": trackAt(tr, tt + 60).
```
- `simFeasible`은 `S.o2`, `S.t`를 쓴다. 로컬 귀환 트리의 t는 이미 경사별 속도로 누적돼 있으니 그대로 둔다.
- 남은 거리 로그("거점까지 x km 남음")는 `len − 보간 거리`로 계산한다.

## 사용자가 정할 것: 450 g 예시
- 새 모델로 sol 1282 왕복을 계산했다 [계산, 산소 최소 경로, k = 1]: 가는 길 254.1 g + 귀환 248.2 g + 예비 45.0 g = **547 g**
- 이전 모델에서는 196 + 184 + 예비 = 약 419 g이라 450 g에 맞았다. 그래서 "평소대로면 되지만 60분부터 25% 급증하면 경보가 있어야 산다"는 대비가 나왔다.
- 새 모델에서는 450 g으로 급증이 없어도 왕복할 수 없다. 예시가 보여 주려던 "급증 → 경보"의 의미를 잃는다.
- 선택지:
  - (가) 산소량을 올린다(대략 560~640 g 사이에서 대비가 나올 것으로 추정). 단, 압력 방식의 "가득 찬 탱크 540 g" 가정을 넘는다.
  - (나) 450 g을 두고 목적지를 더 가까운 웨이포인트로 바꾼다. 탱크 가정과 맞는다.
  - (다) 그대로 두고 설명만 "처음부터 무리한 계획" 예시로 바꾼다.
- 정확한 값은 병합 후 시뮬레이션으로 찾는다.
